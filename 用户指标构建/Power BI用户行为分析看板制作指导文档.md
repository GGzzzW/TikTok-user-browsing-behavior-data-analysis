# Power BI 用户行为分析看板制作指导文档

> 适用工具：Power BI Desktop  
> 数据库：PostgreSQL  
> 核心数据表：public.user_features  
> 看板页数：3 页

---

## 第一部分：项目说明

### 1. 项目目的

本项目基于抖音用户浏览行为数据，从用户行为表现、内容消费特征和地域特征三个维度构建用户画像，并在 Power BI 中制作用户行为分析看板。

看板主要用于回答以下问题：

- 用户总体产生了多少浏览、点赞和完播行为？
- 浏览量、点赞量和完播量是否集中在少数用户？
- 浏览量、点赞量、完播量及相关比例之间呈现什么关系？
- 用户观看内容的作品、作者、配乐、频道和视频时长特征如何分布？
- 用户记录涉及的城市数量和观看作品发布城市数量有什么关系？

本项目只描述数据中可观察到的行为特征，不将相关关系解释为因果关系。

### 2. 数据来源与数据表

PostgreSQL 中包含：

- 原始明细表：public.douyin_dataset
- 用户特征表：public.user_features

本次 Power BI 看板主要加载 public.user_features。

user_features 的数据粒度是：

> 一行代表一个用户，uid 是用户唯一标识。

### 3. user_features 字段口径

| 字段 | 中文名称 | 定义 |
| --- | --- | --- |
| uid | 用户 ID | 用户唯一标识 |
| view_count | 浏览量 | 用户浏览行为记录总数 |
| like_count | 点赞量 | 用户点赞行为总数 |
| like_rate | 点赞率 | like_count ÷ view_count |
| finished_count | 完播量 | 用户完整观看行为总数 |
| finished_item_count | 完整观看作品数 | 至少被该用户完整观看过一次的不同作品数 |
| finished_rate | 完播率 | finished_count ÷ view_count |
| item_count | 观看作品数 | 用户观看过的不同作品数 |
| repeat_view_rate | 重复观看率 | (view_count - item_count) ÷ view_count |
| author_count | 观看作者数 | 用户观看过的不同作者数 |
| music_count | 观看配乐数 | 用户观看作品涉及的不同配乐数 |
| channel_count | 浏览频道数 | 用户浏览过的不同频道数 |
| avg_view_item_duration | 用户所浏览视频平均时长 | 每条浏览记录对应视频本身时长的平均值 |
| user_city_count | 用户出现城市数 | 用户记录中出现的不同 user_city 编号数 |
| item_city_count | 观看作品城市数 | 用户观看作品涉及的不同发布城市编号数 |

### 4. 分析限制

制作和解读看板时必须遵守：

1. 数据中没有用户行为发生时间。
2. real_time、H、date 是作品发布时间，不是用户浏览时间。
3. 不分析 DAU、用户活跃天数、最近活跃时间、活跃时间段或日均活跃量。
4. duration_time 是视频本身时长，不是用户实际观看时长。
5. like 表示点赞，不能称为点击。
6. user_city_count 不能解释为用户真实去过的城市数量。
7. 城市、频道、作者、作品和音乐目前都是编号。
8. 相关关系不能写成因果关系。
9. 结论必须区分数据事实与业务推测。

## 第二部分：Power BI 数据准备

### 1. 连接 PostgreSQL

1. 打开 Power BI Desktop。
2. 选择“主页”→“获取数据”→“PostgreSQL 数据库”。
3. 服务器填写 PostgreSQL 地址，例如 127.0.0.1:5432。
4. 数据库填写项目数据库名称。
5. 数据连接模式优先选择“导入”。
6. 输入 PostgreSQL 用户名和密码。
7. 在导航器中选择 public.user_features。
8. 选择“转换数据”，先进入 Power Query 检查数据，不要立刻制作图表。

本项目数据规模适合先使用导入模式。导入模式通常比 DirectQuery 更适合求排名、累计贡献率和大量散点计算。

### 2. 导入后检查

在 Power Query 中依次检查：

1. 表名是否为 user_features。
2. uid 是否存在空值或重复值。
3. 行数是否等于 PostgreSQL 中 user_features 的用户数。
4. 所有 count 字段是否为整数。
5. 三个 rate 字段是否处于 0～1。
6. avg_view_item_duration 是否为小数。
7. 是否存在导入错误、空白值或异常负数。

可在 PostgreSQL 中使用以下结果作为核对基准：

~~~SQL
SELECT
    COUNT(*) AS row_count,
    COUNT(DISTINCT uid) AS user_count
FROM public.user_features;
~~~

row_count 应当等于 user_count。

### 3. 推荐数据类型与格式

| 字段 | Power BI 推荐类型 | 默认汇总 | 显示格式 |
| --- | --- | --- | --- |
| uid | 文本 | 不汇总 | 常规 |
| view_count | 整数 | 求和 | 千分位、0 位小数 |
| like_count | 整数 | 求和 | 千分位、0 位小数 |
| like_rate | 小数 | 不汇总或平均值 | 百分比、1～2 位小数 |
| finished_count | 整数 | 求和 | 千分位、0 位小数 |
| finished_item_count | 整数 | 求和 | 千分位、0 位小数 |
| finished_rate | 小数 | 不汇总或平均值 | 百分比、1～2 位小数 |
| item_count | 整数 | 求和 | 千分位、0 位小数 |
| repeat_view_rate | 小数 | 不汇总或平均值 | 百分比、1～2 位小数 |
| author_count | 整数 | 求和 | 千分位、0 位小数 |
| music_count | 整数 | 求和 | 千分位、0 位小数 |
| channel_count | 整数 | 求和 | 千分位、0 位小数 |
| avg_view_item_duration | 小数 | 不汇总或平均值 | 2 位小数 |
| user_city_count | 整数 | 求和 | 0 位小数 |
| item_city_count | 整数 | 求和 | 0 位小数 |

uid 虽然可能在数据库中是数字，但它是标识符而不是可运算数值。将其设置为文本并选择“不汇总”，可以避免 Power BI 自动对 uid 求和。

### 4. 百分比格式

like_rate、finished_rate、repeat_view_rate 已经是 0～1 的小数。选中字段后，在“列工具”中设置：

- 格式：百分比
- 小数位数：1 或 2

不要再乘以 100。

### 5. 隐藏字段

- 如果只加载 user_features，不需要隐藏其中字段。
- 如果同时加载 douyin_dataset，可在模型视图中将原始明细字段从报表视图隐藏，避免初学者误用。
- 后续创建的排序辅助列可以设置为“在报表视图中隐藏”。
- 贡献曲线辅助表用于专门图表，不应与 user_features 建立关系。

### 6. 计算列与度量值的分工

- 度量值：用于总量、总体比例、人均值等随筛选变化的结果。
- 计算列：用于浏览量分组、比例分组、象限标签等逐行分类。
- 计算表：用于累计贡献曲线。

原则上不要用计算列保存总浏览量、总体点赞率等汇总结果。

## 第三部分：基础 DAX 度量值

在“建模”→“新建度量值”中依次建立以下度量值。建议把它们统一放在 user_features 表，或单独建立“度量值”表。

### 1. 用户数量

~~~DAX
用户数量 =
DISTINCTCOUNT('user_features'[uid])
~~~

- 用途：用户规模 KPI、分布图 Y 轴。
- 格式：整数，千分位，0 位小数。

### 2. 总浏览量

~~~DAX
总浏览量 =
SUM('user_features'[view_count])
~~~

- 用途：浏览规模 KPI、累计贡献检查。
- 格式：整数，千分位，0 位小数。

### 3. 总点赞量

~~~DAX
总点赞量 =
SUM('user_features'[like_count])
~~~

- 用途：点赞规模 KPI。
- 格式：整数，千分位，0 位小数。

### 4. 整体点赞率

~~~DAX
整体点赞率 =
DIVIDE(
    [总点赞量],
    [总浏览量],
    0
)
~~~

- 用途：总体点赞表现 KPI。
- 格式：百分比，2 位小数。
- 注意：不能直接平均用户级 like_rate。

### 5. 总完播量

~~~DAX
总完播量 =
SUM('user_features'[finished_count])
~~~

- 用途：完播规模 KPI。
- 格式：整数，千分位，0 位小数。

### 6. 整体完播率

~~~DAX
整体完播率 =
DIVIDE(
    [总完播量],
    [总浏览量],
    0
)
~~~

- 用途：总体完播表现 KPI。
- 格式：百分比，2 位小数。
- 注意：不能直接平均用户级 finished_rate。

### 7. 整体重复观看率

~~~DAX
整体重复观看率 =
DIVIDE(
    SUM('user_features'[view_count])
        - SUM('user_features'[item_count]),
    SUM('user_features'[view_count]),
    0
)
~~~

- 用途：总体重复浏览程度 KPI。
- 格式：百分比，2 位小数。
- 注意：不能直接平均 repeat_view_rate。

### 8. 人均浏览量

~~~DAX
人均浏览量 =
DIVIDE(
    [总浏览量],
    [用户数量],
    0
)
~~~

- 用途：衡量平均每名用户产生多少条浏览记录。
- 格式：小数，2 位。

### 9. 用户平均点赞率

~~~DAX
用户平均点赞率 =
AVERAGE('user_features'[like_rate])
~~~

- 用途：用户四象限阈值或辅助参考线。
- 格式：百分比，2 位小数。
- 注意：它是用户级点赞率的算术平均值，不等于整体点赞率。

### 10. 用户平均完播率

~~~DAX
用户平均完播率 =
AVERAGE('user_features'[finished_rate])
~~~

- 用途：用户四象限阈值或辅助参考线。
- 格式：百分比，2 位小数。
- 注意：它不等于整体完播率。

## 第四部分：第 1 页制作指导——用户整体行为概览

### 1. 页面作用与布局

页面名称：用户整体行为概览

建议布局：

- 顶部：页面标题和 8 张 KPI 卡片。
- 中部：浏览量、点赞量、完播量累计贡献曲线。
- 底部：浏览量、点赞率、完播率分布图。

页面重点是快速说明用户规模、总体行为表现、指标集中度和用户分布。

### 2. KPI 卡片组

图表名称：核心用户行为 KPI

- 推荐视觉对象：卡片，新版卡片可在一个对象中容纳多个度量值。
- 分析目的：集中显示整体规模与核心比例。
- X 轴：不使用。
- Y 轴：不使用。
- 图例：不使用。
- 值：用户数量、总浏览量、总点赞量、整体点赞率、总完播量、整体完播率、整体重复观看率、人均浏览量。
- 详细信息：不使用。
- 气泡大小：不使用。
- 工具提示：可加入相邻指标，例如整体点赞率卡片加入总点赞量和总浏览量。
- 筛选器：继承页面筛选器。
- 需要的 DAX：第三部分中的 8 个基础度量值。
- 需要的计算列：无。
- 排序方式：无。
- 格式设置：总量使用千分位；比例使用百分比；人均浏览量保留 2 位小数。

具体制作步骤：

1. 在可视化窗格中选择“卡片”。
2. 将“用户数量”拖入值。
3. 复制该卡片 7 次，依次替换为其余 KPI。
4. 将卡片排成两行或一行，保持相同宽度和高度。
5. 开启类别标签，关闭不必要的背景图标。
6. 设置总量为 0 位小数和千分位。
7. 设置比例为百分比并保留 2 位小数。
8. 检查卡片没有使用 user_features[like_rate] 的简单求和。

结果检查方法：

- 用户数量应等于 user_features 行数。
- 总浏览量应等于 view_count 求和。
- 整体点赞率应等于总点赞量除以总浏览量。
- 所有比例应处于 0%～100%。

结果解读方法：

- 先描述规模，再描述比例。
- 不把比例高低直接解释为用户价值高低。

### 3. 三张累计贡献曲线

图表名称：浏览量／点赞量／完播量累计贡献曲线

- 推荐视觉对象：折线图。
- 分析目的：观察行为指标是否集中在少数用户。
- X 轴：贡献曲线[累计用户占比]。
- Y 轴：贡献曲线[累计指标占比]，汇总方式选择最大值。
- 图例：单图时不使用；合并展示时使用贡献曲线[指标]。
- 值：累计指标占比。
- 详细信息：不使用。
- 气泡大小：不使用。
- 工具提示：指标、指标排名、指标值、累计用户占比、累计指标占比。
- 筛选器：单张图分别筛选指标为浏览量、点赞量或完播量。
- 需要的 DAX：第五部分的贡献曲线计算表和计算列。
- 需要的计算列：累计用户占比、累计指标占比等。
- 排序方式：累计用户占比升序。
- 格式设置：X、Y 轴均显示百分比；范围建议设置为 0～100%。

具体制作步骤和检查方法见第五部分。

### 4. 用户浏览量分布

图表名称：用户浏览量分布

- 推荐视觉对象：簇状柱形图。
- 分析目的：观察不同浏览量区间的用户数量。
- X 轴：user_features[浏览量分组]。
- Y 轴：用户数量。
- 图例：不使用。
- 值：用户数量。
- 详细信息：不使用。
- 气泡大小：不使用。
- 工具提示：用户数量、该组用户平均点赞率、该组用户平均完播率。
- 筛选器：排除空白组。
- 需要的 DAX：用户数量。
- 需要的计算列：浏览量分组。
- 排序方式：按分组标签前缀升序。
- 格式设置：Y 轴整数千分位；开启数据标签。

具体制作步骤：

1. 先按第八部分创建“浏览量分组”计算列。
2. 插入簇状柱形图。
3. 将浏览量分组拖入 X 轴。
4. 将用户数量拖入 Y 轴。
5. 确认用户数量采用 DISTINCTCOUNT(uid)。
6. 按浏览量分组升序排序。
7. 打开数据标签，关闭过密的网格线。
8. 将用户平均点赞率、用户平均完播率加入工具提示。

结果检查方法：

- 所有柱子的用户数之和应等于用户数量。
- 分组顺序应从低浏览量到高浏览量。

结果解读方法：

- 描述用户主要集中在哪些浏览量区间。
- 长尾分布只能描述行为差异，不能直接定义用户价值。

### 5. 用户点赞率分布

图表名称：用户点赞率分布

- 推荐视觉对象：簇状柱形图。
- 分析目的：观察用户级点赞率的分布。
- X 轴：user_features[点赞率分组]。
- Y 轴：用户数量。
- 图例：不使用。
- 值：用户数量。
- 详细信息：不使用。
- 气泡大小：不使用。
- 工具提示：用户数量、平均浏览量、整体点赞率。
- 筛选器：排除空白组。
- 需要的 DAX：用户数量、整体点赞率。
- 需要的计算列：点赞率分组。
- 排序方式：从 0% 到 100%。
- 格式设置：数据标签显示整数；标题必须写“点赞率”而不是“点击率”。

具体制作步骤：

1. 创建点赞率分组计算列。
2. 插入簇状柱形图。
3. 将点赞率分组放入 X 轴。
4. 将用户数量放入 Y 轴。
5. 将整体点赞率和人均浏览量放入工具提示。
6. 按标签前缀升序排序。
7. 检查 like_rate 没有再次乘以 100。

结果检查方法：

- 各组用户数合计应等于总用户数。
- 不应出现低于 0% 或高于 100% 的组。

结果解读方法：

- 说明用户点赞率主要集中区间。
- 可谨慎推测互动意愿差异，但不能解释其原因。

### 6. 用户完播率分布

图表名称：用户完播率分布

- 推荐视觉对象：簇状柱形图。
- 分析目的：观察用户级完播率分布。
- X 轴：user_features[完播率分组]。
- Y 轴：用户数量。
- 图例：不使用。
- 值：用户数量。
- 详细信息：不使用。
- 气泡大小：不使用。
- 工具提示：用户数量、平均浏览量、整体完播率。
- 筛选器：排除空白组。
- 需要的 DAX：用户数量、整体完播率。
- 需要的计算列：完播率分组。
- 排序方式：从 0% 到 100%。
- 格式设置：标签为百分比区间，Y 轴为整数。

具体制作步骤：

1. 创建完播率分组计算列。
2. 插入簇状柱形图。
3. 将完播率分组放入 X 轴。
4. 将用户数量放入 Y 轴。
5. 将整体完播率加入工具提示。
6. 按分组标签前缀升序排序。
7. 检查 finished_rate 的字段格式为百分比。

结果检查方法：

- 所有组用户数之和应等于用户数量。
- 不应出现超出 0%～100% 的值。

结果解读方法：

- 描述完播率集中区间和分布形态。
- 完播率较高可能与视频内容、视频时长等因素有关，但当前图表不能证明原因。

## 第五部分：累计贡献曲线专项指导

### 1. 推荐实现方式

最稳定、最适合初学者的方法是创建一张断开关系的 DAX 计算表，统一保存浏览量、点赞量和完播量的用户排名及累计占比。

优点：

- 三种指标复用同一套逻辑。
- 不依赖复杂视觉上下文。
- 刷新数据时会重新计算。
- 同值用户可以按一个整体处理。

限制：

- 该计算表是刷新时计算的，不会随普通 user_features 切片器动态变化。
- 因此贡献曲线适合展示全体用户的整体集中度。
- 不要将贡献曲线表与 user_features 建立关系。

### 2. 创建贡献曲线计算表

选择“建模”→“新建表”，输入：

~~~DAX
贡献曲线 =
UNION(
    SELECTCOLUMNS(
        'user_features',
        "指标", "浏览量",
        "uid", 'user_features'[uid],
        "指标值", 'user_features'[view_count]
    ),
    SELECTCOLUMNS(
        'user_features',
        "指标", "点赞量",
        "uid", 'user_features'[uid],
        "指标值", 'user_features'[like_count]
    ),
    SELECTCOLUMNS(
        'user_features',
        "指标", "完播量",
        "uid", 'user_features'[uid],
        "指标值", 'user_features'[finished_count]
    )
)
~~~

### 3. 用户排名

在贡献曲线表中新建计算列：

~~~DAX
指标排名 =
VAR 当前指标 = '贡献曲线'[指标]
VAR 当前指标值 = '贡献曲线'[指标值]
RETURN
RANKX(
    FILTER(
        ALL('贡献曲线'),
        '贡献曲线'[指标] = 当前指标
    ),
    '贡献曲线'[指标值],
    当前指标值,
    DESC,
    DENSE
)
~~~

这里使用 RANKX 按指标值从大到小排名。DENSE 表示同值用户排名相同，下一名连续递增。

### 4. 同值用户处理

累计曲线不能简单使用“排名 ÷ 用户数”作为累计用户占比，因为同值用户共享排名。更稳妥的办法是直接统计“指标值大于或等于当前值”的用户数，将同值用户作为一个整体纳入累计结果。

创建计算列：

~~~DAX
累计用户数 =
VAR 当前指标 = '贡献曲线'[指标]
VAR 当前指标值 = '贡献曲线'[指标值]
RETURN
COUNTROWS(
    FILTER(
        ALL('贡献曲线'),
        '贡献曲线'[指标] = 当前指标
            && '贡献曲线'[指标值] >= 当前指标值
    )
)
~~~

创建指标用户总数：

~~~DAX
指标用户总数 =
VAR 当前指标 = '贡献曲线'[指标]
RETURN
COUNTROWS(
    FILTER(
        ALL('贡献曲线'),
        '贡献曲线'[指标] = 当前指标
    )
)
~~~

创建累计用户占比：

~~~DAX
累计用户占比 =
DIVIDE(
    '贡献曲线'[累计用户数],
    '贡献曲线'[指标用户总数],
    0
)
~~~

### 5. 累计指标值与累计指标占比

创建累计指标值：

~~~DAX
累计指标值 =
VAR 当前指标 = '贡献曲线'[指标]
VAR 当前指标值 = '贡献曲线'[指标值]
RETURN
SUMX(
    FILTER(
        ALL('贡献曲线'),
        '贡献曲线'[指标] = 当前指标
            && '贡献曲线'[指标值] >= 当前指标值
    ),
    '贡献曲线'[指标值]
)
~~~

创建指标总值：

~~~DAX
指标总值 =
VAR 当前指标 = '贡献曲线'[指标]
RETURN
SUMX(
    FILTER(
        ALL('贡献曲线'),
        '贡献曲线'[指标] = 当前指标
    ),
    '贡献曲线'[指标值]
)
~~~

创建累计指标占比：

~~~DAX
累计指标占比 =
DIVIDE(
    '贡献曲线'[累计指标值],
    '贡献曲线'[指标总值],
    0
)
~~~

把累计用户占比、累计指标占比格式设置为百分比，保留 1～2 位小数。

### 6. 制作浏览量累计贡献曲线

1. 插入折线图。
2. 将累计用户占比放入 X 轴。
3. 将累计指标占比放入 Y 轴。
4. 将 Y 轴汇总方式设置为“最大值”。
5. 在视觉对象筛选器中，把指标筛选为“浏览量”。
6. 将指标排名、指标值、累计用户数、累计指标值加入工具提示。
7. 将 X 轴类型设置为连续。
8. 按累计用户占比升序排序。
9. 将 X、Y 轴格式设置为百分比。
10. 标题设置为“浏览量累计贡献曲线”。

点赞量和完播量曲线只需复制该图，并分别把指标筛选为“点赞量”和“完播量”。

也可以把三条曲线放在同一折线图中：

- X 轴：累计用户占比
- Y 轴：累计指标占比
- 图例：指标

但求职作品集中，三张小图通常更容易比较各指标集中程度。

### 7. 理论检查

曲线应满足：

1. X 轴从较小占比逐渐增加到 100%。
2. Y 轴不应下降。
3. 最后一个有效点应达到 100% 用户和 100% 指标值。
4. 浏览量总值应等于总浏览量。
5. 点赞量总值应等于总点赞量。
6. 完播量总值应等于总完播量。

如果最后没有达到 100%，检查：

- 是否错误使用平均值代替求和；
- 是否在视觉筛选器中排除了 0 值用户；
- 是否对 X 或 Y 使用了错误汇总方式；
- 指标总值是否在当前指标范围内计算；
- 数据中该指标是否全部为 0。

曲线通常不会从严格的 (0%, 0%) 开始，因为第一点代表排名最前的一组用户。这不属于计算错误。

### 8. 二八分布解读

在图上观察累计用户占比为 20% 附近时，累计指标占比是多少。不要预设结果一定是 80%。

正确表达：

> 前 X% 的用户贡献了约 Y% 的浏览量，浏览行为在用户之间呈现一定程度的集中。

不正确表达：

> 20% 的高价值用户创造了 80% 的价值。

当前数据没有收入、留存或成本指标，不能直接定义用户价值。

### 4. 完播率与点赞率四象限散点图

图表名称：用户完播率与点赞率四象限

- 推荐视觉对象：散点图。
- 分析目的：按相对平均水平描述用户互动类型。
- X 轴：finished_rate。
- Y 轴：like_rate。
- 图例：互动四象限。
- 值：不使用。
- 详细信息：uid。
- 气泡大小：view_count。
- 工具提示：uid、view_count、finished_rate、like_rate、repeat_view_rate。
- 筛选器：可设置最低浏览量门槛，减少极少浏览记录造成的极端比例，但必须在标题或注释中披露。
- 需要的 DAX：用户平均点赞率、用户平均完播率。
- 需要的计算列：互动四象限。
- 排序方式：无。
- 格式设置：X、Y 轴均为百分比，范围 0%～100%。

创建四象限计算列：

~~~DAX
互动四象限 =
VAR 平均点赞率 =
    CALCULATE(
        AVERAGE('user_features'[like_rate]),
        ALL('user_features')
    )
VAR 平均完播率 =
    CALCULATE(
        AVERAGE('user_features'[finished_rate]),
        ALL('user_features')
    )
RETURN
SWITCH(
    TRUE(),
    'user_features'[finished_rate] >= 平均完播率
        && 'user_features'[like_rate] >= 平均点赞率,
        "高完播率－高点赞率",
    'user_features'[finished_rate] >= 平均完播率
        && 'user_features'[like_rate] < 平均点赞率,
        "高完播率－低点赞率",
    'user_features'[finished_rate] < 平均完播率
        && 'user_features'[like_rate] >= 平均点赞率,
        "低完播率－高点赞率",
    "低完播率－低点赞率"
)
~~~

具体制作步骤：

1. 插入散点图。
2. 将 finished_rate 放入 X 轴。
3. 将 like_rate 放入 Y 轴。
4. 将 uid 放入详细信息。
5. 将 view_count 放入气泡大小。
6. 将互动四象限放入图例。
7. 将相关字段放入工具提示。
8. 打开“分析”窗格。如果当前版本支持平均线，分别为 X、Y 轴添加平均线。
9. 如果只支持常量线，先用卡片查看用户平均完播率和用户平均点赞率，再把数值分别填入 X、Y 轴常量线。
10. 将两条线设置为浅灰虚线，避免遮挡数据点。

结果检查方法：

- X、Y 值都应在 0%～100%。
- 四个图例分类应与两条平均线位置一致。
- 浏览量极低的用户可能出现 0% 或 100% 的极端比例。

四象限解释：

- 高完播率－高点赞率：相对更充分观看且更常点赞。
- 高完播率－低点赞率：相对更常完播，但较少显式点赞。
- 低完播率－高点赞率：较少完播但存在较高点赞比例。
- 低完播率－低点赞率：两项比例均低于用户平均水平。

这些标签只是行为类型，不能直接命名为高价值、低价值、优质或流失用户，因为当前数据没有收入、留存和时间信息。

### 2. 切片器样式

1. 分组数量较少时使用横向按钮或磁贴。

3. 默认开启“全选”。
4. 同类切片器保持相同宽度。

### 3. 图表交叉筛选

建议：

- 分布图筛选 KPI 卡片和用户明细表。
- 散点图筛选用户明细表。
- 四象限图筛选本页其他用户级图表。
- 第 3 页分布图可筛选两个关系散点图。

- 不让单张 KPI 卡片反向筛选其他图表。

5. 对贡献曲线选择“无影响”。
6. 完成后再次点击“编辑交互”退出。
7. 逐个测试切片器，确认用户数量与明细行数同步变化。

如果希望切片器跨页面同步：

1. 选择“视图”→“同步切片器”。
2. 勾选需要同步的页面。
3. 决定该切片器在其他页面是否可见。

## 第十二部分：数据口径与常见错误

1. like_count 是点赞量，不能写成点击量。
2. like_rate 是用户级点赞率，不能求和。
3. 整体点赞率必须用总点赞量除以总浏览量，不能简单平均 like_rate。
4. 整体完播率必须用总完播量除以总浏览量，不能简单平均 finished_rate。
5. 整体重复观看率必须重新按总浏览量和观看作品数计算，不能简单平均 repeat_view_rate。
6. avg_view_item_duration 只能写成“用户所浏览视频平均时长”，不能写成“用户平均观看时长”。
7. duration_time 是视频本身时长，不是实际观看时长。
8. user_city_count 必须写成“用户出现城市数”，不能写成“用户去过城市数”。
9. real_time、H、date 是作品发布时间，不能用来分析用户活跃时间。
10. 当前数据不能分析 DAU、最近活跃时间、活跃时间段和活跃天数。
11. uid 是标识符，不能求和。
12. 散点图必须把 uid 放入详细信息，否则容易只显示一个聚合点。
13. 百分比字段已经是 0～1，不能再次乘以 100。
14. 完播量和完整观看作品数含义不同，不能混用。
15. 浏览量和观看作品数含义不同，重复浏览会增加浏览量但不会增加不同作品数。
16. 贡献曲线的计算表不要与 user_features 建立关系。
17. 贡献曲线是刷新时计算的静态全体曲线，不会响应 user_features 普通切片器。
18. 分组边界是初始建议，必须根据实际分布调整。
19. 比例极端值可能来自浏览量很小的用户，解释时应同时查看 view_count。
20. 城市、频道、作者、作品、音乐是编号，不能在没有维表的情况下展示成名称。
21. 不能把散点图中的相关关系写成因果关系。
22. “高于平均”只是相对描述，不能自动等同于高价值用户。
23. 任何筛选条件，尤其最低浏览量门槛，都应在页面注释或标题中披露。
24. 发布看板前，应逐项核对 Power BI 总量与 PostgreSQL 查询结果。
